⚠️ UI CONSISTENCY AUDIT

Widget Styling Across Dashboard, Reports, and Settings

Critical inconsistencies found in widget component usage

🔍 Executive Summary

FINDINGS: 3 CRITICAL UI INCONSISTENCIES
  • Settings Module Inconsistency: Homepage customization shows a TABLE UI instead of demonstrating actual widget previews (unlike Dashboard & Reports)
  • Dashboard vs Reports Widget Styling: Dashboard uses KPICard (solid pastel fills), Reports use WidgetCard (glassmorphism) — different visual languages
  • Dark Mode Background Mismatch: KPICard uses `#18181B`, WidgetCard uses `#0A0A0A` — inconsistent layering depth in dark mode

ISSUE #1: Settings Module Homepage Customization Critical

❌ Homepage Customization UI Is NOT Widget-Preview Based
The Settings > "Customize Home page" panel shows a TABLE interface for managing homepages, not actual widget previews. This is inconsistent with how Dashboard and Reports display widgets.

Current Implementation

File: app/settings/page.tsx (lines 3056-3196) - CustomizeHomepagePanel function

What Dashboard Shows

Expected Fix

The Settings module should show a PREVIEW of each homepage's widgets (similar to `/home/[id]/edit`), not just a table of metadata. Users should see:
  • Visual preview of each homepage (grid/card layout with actual widgets)
  • Quick edit/delete buttons overlaid on the preview
  • Same card styling as Dashboard widgets

ISSUE #2: Dashboard vs Reports Widget Styling Medium

⚠️ Dashboard and Reports Use DIFFERENT Widget Components
Dashboard widgets (KPICard) use solid pastel fill backgrounds with hover-lift effects. Report widgets (WidgetCard + MetricCard) use glassmorphism with semi-transparent backgrounds. This creates inconsistent visual language across the application.

Root Cause

Dashboard was built with KPICard for solid, distinctive card backgrounds (using the complementary card palette: Lavender, Sage, Peach, etc.). Reports were built later with WidgetCard for a more modern glassmorphic aesthetic. No design decision was made to unify them.

ISSUE #3: Dark Mode Background Color Mismatch Medium

Dashboard KPICard uses `#18181B` for dark mode backgrounds. Reports WidgetCard uses `#0A0A0A` (same as page background). This breaks the visual hierarchy and layering depth in dark mode.

✅ Recommendations

1. Unify Widget Components (High Priority)

Choose ONE widget component to use across Dashboard, Reports, and Settings:
  • Option A: Use KPICard everywhere — Solid pastel fills are distinctive and on-brand with complementary card palette
  • Option B: Use WidgetCard everywhere — Modern glassmorphism is trendy, but lighter feel
  • Recommended: Option A (KPICard) — Better aligns with existing complementary card palette

2. Fix Dark Mode Backgrounds (High Priority)

  • Update WidgetCard to use `#18181B` (not `#0A0A0A`) for card background in dark mode
  • Verify all cards have proper depth layering: Page (#0A0A0A) → Card (#18181B) → Interactive (#27272A)

3. Improve Settings Homepage Customization (Medium Priority)

  • Replace table UI with preview cards showing actual homepage layouts
  • Allow users to see what each homepage will look like before activating
  • Maintain edit/delete/clone actions in an overlay menu

4. Standardize Hover Effects (Low Priority)

  • All widgets should have consistent hover effects (shadow + optional lift transform)
  • Document hover behavior in component library
