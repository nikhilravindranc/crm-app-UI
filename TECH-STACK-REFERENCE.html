⚙️ Tech Stack Reference

CRM Development Standards & Architecture

Complete setup guide for building apps with the CRM design system

🎯 Overview

The CRM uses a modern, performant tech stack optimized for rapid development, scalability, and maintaining the design system consistency across modules.

Core Technologies

🚀 Frontend Framework Primary

Next.js 15.0.3

React meta-framework with App Router, Server Components, and built-in routing. Uses Turbopack for ultra-fast builds.

⚛️ UI Library Primary

React 19.0.0

Latest React with hooks (useState, useContext, useEffect) for state management and side effects.

🎨 Styling Primary

Tailwind CSS 3.4.14

Utility-first CSS framework with arbitrary values for design system colors. Supports dark mode with class-based strategy.

🧩 Component Library Primary

Material-UI (MUI) 6.1.6

Pre-built components (Button, Input, Select, Table, Modal, etc.) with full customization via sx prop and theme overrides.

🔤 Type Safety Primary

TypeScript 5.6.3

Full TypeScript support for type safety, better IDE autocomplete, and compile-time error detection.

📊 Data Visualization Secondary

Recharts 2.13.3

Composable React charting library for dashboard KPI cards, trends, and analytics.

🎯 Icons Secondary

Phosphor Icons 2.1.10

Extensive icon library with consistent design. Easy to color and size dynamically.

📑 Tables Secondary

MUI Data Grid 7.29.13

Enterprise-grade table component with sorting, filtering, pagination, and row selection.

🛠️ Project Setup Guide

Step-by-step instructions for setting up a new app using this tech stack.

1. Create Next.js Project

npx create-next-app@latest my-app --typescript --tailwind --eslint cd my-app

2. Install Core Dependencies

npm install @mui/material @mui/icons-material @emotion/react @emotion/styled npm install @phosphor-icons/react recharts @mui/x-data-grid

3. Project Structure

my-app/ ├── app/ │ ├── layout.tsx (Root layout with theme provider) │ ├── page.tsx (Dashboard/home) │ ├── [module]/ │ │ ├── page.tsx (List view) │ │ └── [id]/ │ │ └── page.tsx (Detail view) │ └── settings/ │ └── page.tsx (Settings page) ├── components/ │ ├── Layout/ │ │ ├── Sidebar.tsx │ │ ├── TopBar.tsx │ │ └── MainLayout.tsx │ ├── [module]/ │ │ ├── ListView.tsx │ │ ├── DetailView.tsx │ │ └── Forms.tsx │ └── Common/ │ ├── Button.tsx │ ├── Input.tsx │ └── Modal.tsx ├── context/ │ └── ThemeContext.tsx (Dark mode provider) ├── styles/ │ └── globals.css (Global styles) ├── lib/ │ └── constants.ts (Color system, spacing, etc.) └── middleware.ts (Auth middleware, routing guards)

4. Configure Tailwind

// tailwind.config.ts export default { darkMode: 'class', theme: { extend: { colors: { primary: { DEFAULT: '#1D4ED8', light: '#60A5FA', dark: '#0C2472', }, surface: '#EFF6FF', tint: '#E3ECFC', }, }, }, }

5. Set Up Theme Context

// context/ThemeContext.tsx import React, { createContext, useState } from 'react' interface ThemeContextType { isDark: boolean toggleTheme: () => void } export const ThemeContext = createContext<ThemeContextType | undefined>(undefined) export function ThemeProvider({ children }: { children: React.ReactNode }) { const [isDark, setIsDark] = useState(false) return ( <ThemeContext.Provider value={{ isDark, toggleTheme: () => setIsDark(!isDark) }}> <div data-theme={isDark ? 'dark' : 'light'}> {children} </div> </ThemeContext.Provider> ) }

6. Create Layout Wrapper

// app/layout.tsx import { ThemeProvider } from '@/context/ThemeContext' export default function RootLayout({ children }: { children: React.ReactNode }) { return ( <html> <body> <ThemeProvider> <MainLayout> {children} </MainLayout> </ThemeProvider> </body> </html> ) }

🎨 Styling Architecture

A hybrid approach combining Tailwind CSS for responsive utilities and MUI for complex components.

Three-Layer Styling Strategy

Layer 1: Global Styles

Foundation styling via globals.css

@tailwind base; @tailwind components; @tailwind utilities; body { @apply bg-[#EFF6FF] text-[#0C2472]; } [data-theme="dark"] body { @apply bg-[#0A0A0A] text-[#D4D4D8]; }

Layer 2: Component Styles

Tailwind utilities + MUI sx prop

<Button className="px-5 py-2 rounded-lg hover:shadow-lg transition-all" sx={{ background: '#1D4ED8', '&:hover': { background: '#60A5FA' }, '&.dark': { background: '#60A5FA' } }} > Click me </Button>

Color System Implementation

Recommended: CSS Variables for Easy Swapping

Define all brand colors as CSS variables in globals.css, making it trivial to adapt to new brands.

:root { /* Primary Colors */ --color-primary: #1D4ED8; --color-primary-hover: #60A5FA; --color-primary-dark: #0C2472; /* Text Colors */ --color-text-primary: #0C2472; --color-text-secondary: #334155; --color-text-tertiary: #94A3B8; /* Backgrounds */ --color-bg-surface: #EFF6FF; --color-bg-tint: #E3ECFC; --color-bg-subtle: #f9fbff; } [data-theme="dark"] { --color-text-primary: #D4D4D8; --color-text-secondary: #71717A; --color-bg-surface: #0A0A0A; /* ... etc */ } /* Use in components */ .button-primary { background-color: var(--color-primary); color: white; }

Dark Mode Implementation

Strategy: Class-Based + React Context
  • Store dark mode preference in React Context
  • Apply data-theme="dark" or class="dark" to root element
  • Use Tailwind's dark: prefix for utilities: dark:bg-[#0A0A0A]
  • Use MUI's sx prop with conditional styles based on context
  • Persist preference to localStorage for user persistence

🧩 Component Architecture

How to organize and build reusable components following the design system.

Component Hierarchy

// Atomic Design Pattern 1. Atoms (Smallest) ├── Button.tsx ├── Input.tsx ├── Label.tsx └── Badge.tsx 2. Molecules (Combinations) ├── FormGroup.tsx (Label + Input) ├── SearchBar.tsx (Input + Icon + Button) └── Card.tsx (Container + Spacing) 3. Organisms (Complex) ├── Modal.tsx ├── Table.tsx ├── Form.tsx └── Navigation.tsx 4. Templates (Page Layouts) ├── ListTemplate.tsx ├── DetailTemplate.tsx └── FormTemplate.tsx 5. Pages (Complete Views) ├── LeadsList.tsx ├── LeadDetail.tsx └── LeadCreate.tsx

Example: Reusable Button Component

// components/Common/Button.tsx import { useContext } from 'react' import { ThemeContext } from '@/context/ThemeContext' interface ButtonProps { children: React.ReactNode variant?: 'primary' | 'secondary' | 'disabled' className?: string onClick?: () => void } export function Button({ children, variant = 'primary', className = '', onClick }: ButtonProps) { const theme = useContext(ThemeContext) const isDark = theme?.isDark const baseClasses = ` px-5 py-2.5 font-semibold rounded-lg transition-all duration-200 focus:outline-none focus:ring-2 focus:ring-[#93C5FD] ` const variantClasses = { primary: ` bg-[#1D4ED8] text-white hover:bg-[#60A5FA] active:bg-[#0C2472] ${isDark ? 'dark:bg-[#1D4ED8] dark:hover:bg-[#60A5FA]' : ''} `, secondary: ` bg-[#3B82F6] text-white hover:bg-[#60A5FA] `, disabled: ` bg-[#E3ECFC] text-[#94A3B8] cursor-not-allowed dark:bg-[#3F3F46] dark:text-[#52525B] ` } return ( <button className={`${baseClasses} ${variantClasses[variant]} ${className}`} onClick={onClick} disabled={variant === 'disabled'} > {children} </button> ) }

🔄 State Management

Pattern for managing application state using React Context API.

Available Contexts

ThemeContext

Manages dark mode toggle and theme state. Persists to localStorage.

interface ThemeContextType { isDark: boolean toggleTheme: () => void }

AuthContext (Example)

Manages user authentication state and permissions.

interface AuthContextType { user: User | null isAuthenticated: boolean login: (email, password) => Promise logout: () => void }

When to Use Context vs Other Solutions

Use Case Recommended Solution Why
Theme (dark/light), Language React Context Low-frequency updates, small app-level state
User Auth, Permissions React Context + localStorage Session persistence, accessible everywhere
Form State (modal, page) React useState Hook Local component state, easier to manage
API Caching, Complex Data TanStack Query / SWR Not included in base stack—consider for data-heavy apps
Global App State (Redux-level) Zustand or Redux Not included in base stack—add if state becomes complex
Pro Tip: Keep Context API for theme/auth. If you find yourself creating many contexts for data, it's time to evaluate TanStack Query (data fetching) or Zustand (state management).

📦 Build & Deployment

Build configuration and deployment best practices.

Build Configuration

// next.config.ts import type { NextConfig } from "next" const nextConfig: NextConfig = { compiler: { emotion: true, // For MUI Emotion styles }, experimental: { turbopack: { enabled: true, // Ultra-fast builds with Turbopack } } } export default nextConfig

Build Commands

Command Purpose When to Use
npm run dev Start dev server with hot reload Local development (port 3000)
npm run build Production build optimization Before deploying to production
npm start Run production build Production server startup
npm run lint ESLint code quality check Before committing code

Deployment Platforms

Vercel (Recommended)

Native Next.js hosting. Auto-deploy on git push, serverless functions, edge middleware.

vercel deploy

Self-Hosted (Node.js)

Any Node.js server (AWS, DigitalOcean, etc.). More control, higher setup complexity.

npm run build && npm start

Environment Variables

# .env.local (development) NEXT_PUBLIC_API_URL=http://localhost:8000 NEXT_PUBLIC_APP_NAME=CRM # .env.production (production) NEXT_PUBLIC_API_URL=https://api.crm.com NEXT_PUBLIC_APP_NAME=CRM
⚠️ Important: Prefix client-side variables with NEXT_PUBLIC_. Never expose secrets (API keys, passwords) in client-side code.

Best practices for keeping the app fast.

Image Optimization

Code Splitting

Next.js automatically handles:
  • Page-level code splitting (each page is a separate bundle)
  • Dynamic imports for large components: const Modal = dynamic(() => import('./Modal'))
  • Automatic CSS tree-shaking (unused Tailwind classes removed)

Bundle Analysis

# Install and run bundle analyzer npm install -D @next/bundle-analyzer # Set in next.config.ts import { withBundleAnalyzer } from '@next/bundle-analyzer' export default withBundleAnalyzer(nextConfig) # Run build npm run build # Creates .next/analyze

Rendering Strategies

Strategy Best For Example
Static (SSG) Content that doesn't change often (marketing pages, docs) Brand guidelines, help docs
Server Component Fetch data server-side, zero JS shipped Navigation, sidebar (data from DB)
Client Component Interactivity, useState, useEffect, event handlers Forms, modals, filter buttons
Dynamic (SSR) Data changes per request (user-specific content) User dashboard, detail pages

✅ New App Setup Checklist

Complete list of steps to set up a new app using this tech stack.

Initial Setup

  • Create Next.js project with TypeScript and Tailwind
  • Install all core dependencies (see Dependency Matrix)
  • Set up GitHub repository and clone locally
  • Create .env.local with API URLs and config

Project Structure

  • Create folders: app/, components/, context/, lib/, public/
  • Set up folder structure as per "Project Setup Guide"
  • Create TypeScript config (tsconfig.json)
  • Configure ESLint rules

Styling & Theme

  • Create globals.css with design system colors
  • Set up Tailwind config with color palette
  • Create ThemeContext for dark mode
  • Test light and dark mode rendering

Layout & Navigation

  • Build MainLayout component (Sidebar + TopBar + Content)
  • Implement navigation menu using color system
  • Set up auth middleware for protected routes
  • Test responsive layout on mobile

Common Components

  • Create Button (primary, secondary, disabled variants)
  • Create Input and Label components
  • Create Modal/Dialog wrapper component
  • Create Badge and Tag components
  • Create Card wrapper component

API Integration

  • Set up API client (fetch or axios)
  • Create request/response interceptors
  • Handle error states (401, 500, etc.)
  • Implement loading skeletons

Testing & QA

  • Test all components in light mode
  • Test all components in dark mode
  • Verify color contrast (WCAG AA)
  • Test keyboard navigation and tab order
  • Run lighthouse performance audit

Deployment

  • Set up CI/CD pipeline (GitHub Actions recommended)
  • Deploy to Vercel or self-hosted environment
  • Configure production environment variables
  • Set up monitoring and error tracking

🔍 Troubleshooting

Common Issues & Solutions

MUI styles not applying with Tailwind

Problem: MUI components not styled correctly with Tailwind classes.

Solution: Use sx prop for MUI components instead of className. Tailwind applies to custom HTML elements.

// ❌ Wrong <Button className="bg-[#1D4ED8]">Click</Button> // ✅ Correct <Button sx={{ background: '#1D4ED8' }}>Click</Button>

Dark mode not applying to entire page

Problem: dark: classes only apply to some elements.

Solution: Ensure data-theme="dark" is applied to root/html element, not just individual components.

Form validation with MUI TextField

Problem: MUI TextField doesn't show validation errors properly.

Solution: Use error and helperText props on TextField:

<TextField error={!!errors.email} helperText={errors.email?.message} />

Tailwind colors not appearing in build

Problem: Arbitrary Tailwind colors like bg-[#1D4ED8] disappear after build.

Solution: Ensure Tailwind config includes glob pattern for your component files. Add to tailwind.config.ts:

content: [ './app/**/*.{js,ts,jsx,tsx}', './components/**/*.{js,ts,jsx,tsx}', ]

Performance issues with large tables

Problem: Table/DataGrid rendering is slow with 1000+ rows.

Solution: Use MUI DataGrid's virtualization or implement pagination to limit visible rows.
